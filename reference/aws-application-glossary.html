AWS Application Glossary

A compact map of AWS terms as they apply to the Infrastructure AI Agent.

AWS
A cloud platform: you rent managed infrastructure such as storage, compute, databases, networking, identity, and monitoring instead of owning all of it yourself.
Region
A geographic AWS area, such as us-east-1, where your resources live. Pick one close to users and compatible with the services you need.
Availability Zone
An isolated datacenter group inside a Region. Production apps use multiple zones so one datacenter issue does not take the app down.
S3
Object storage for files: inspection images, videos, PDFs, logs, exported datasets, and model artifacts.
Bucket
A top-level S3 container, roughly like a storage namespace. Example: infra-agent-media-prod.
Object Key
The path-like name of a file in S3. Example: inspections/run_123/original/bridge.png.
Presigned URL
A temporary URL that lets a browser upload or download a private S3 object without making the bucket public.
IAM
AWS Identity and Access Management. It controls who or what can access which AWS resources.
IAM Policy
A JSON permission document. Example: allow this app to put objects only into s3://infra-agent-media-prod/uploads/*.
IAM Role
An identity an application or AWS service can assume temporarily. Prefer roles over long-lived access keys in production.
EC2
Virtual machines. Useful when you need server control, custom workers, GPU boxes, or straightforward VM deployment.
ECS/Fargate
Run Docker containers without managing servers directly. A natural next step for your FastAPI/RQ worker containers.
RDS
Managed relational databases such as PostgreSQL. For this project, it would replace self-managed Postgres in Docker.
CloudWatch
AWS logging and monitoring. Useful for API logs, worker errors, latency, alarms, and operational dashboards.

S3 Media Storage Pattern

How uploaded inspection media should be represented when moving from local disk to S3-style object storage.

Core Rule

S3 stores bytes. SQL stores facts about those bytes. Do not store large images/videos directly inside PostgreSQL.

Naming Pattern

bucket: infra-agent-media-dev
key: inspections/{run_id}/original/{media_id}-{safe_filename}

example:
s3://infra-agent-media-dev/inspections/run_123/original/media_abc-bridge-spalling.png

SQL Metadata Row

ColumnPurpose
media_idStable ID used by app, agents, audit logs, and UI.
run_idWhich inspection owns the media.
storage_backendlocal, s3, or minio.
storage_keyS3 object key or local artifact path.
checksum_sha256Detects duplicate/corrupt files and supports audit integrity.
scan_statusnot_scanned, clean, infected, or failed.
preview_urlLocal URL today; later a short-lived presigned URL or app proxy URL.

Presigned URL Pattern

A presigned URL is a temporary permission link. The bucket stays private, but the browser can upload or view one object for a short time.

1. Browser asks API: "I need to upload bridge.png"
2. API checks auth and creates S3 presigned PUT URL
3. Browser uploads bytes directly to S3
4. API stores/updates SQL media metadata
5. UI asks API for preview URL
6. API returns short-lived presigned GET URL

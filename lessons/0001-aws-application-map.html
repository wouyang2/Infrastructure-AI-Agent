Lesson 0001 · AWS for this project

AWS is not one thing. It is the production toolbox around your app.

Your Infrastructure AI Agent already has an app shape: FastAPI, RQ workers, Postgres, Redis, media uploads, RAG artifacts, and reports. AWS services are usually the managed replacements for those responsibilities.

The mental model

Think of AWS as a set of rented building blocks. AWS’s own overview describes cloud computing as on-demand access to compute, databases, storage, applications, and other IT resources with pay-as-you-go pricing.

Storage

S3 stores uploaded images, videos, PDFs, model files, and eval outputs. In your app, it replaces local artifacts/uploads.

Compute

EC2 or ECS/Fargate runs FastAPI and worker containers. In your app, it replaces running Docker only on your laptop.

Database

RDS PostgreSQL stores inspection runs, media metadata, tool idempotency records, and audit events.

Security

IAM controls what the app can do. For example: upload only to one S3 bucket prefix, not delete every bucket in the account.

Networking

VPC, load balancers, security groups decide which services are reachable from the internet and which stay private.

Monitoring

CloudWatch collects logs, metrics, alarms, and operational signals from API and worker services.

Your project’s first AWS use case: uploaded media

You just added SQL media metadata. That is exactly the right setup for S3 because production apps usually store file bytes and file records separately.

1. Browser uploads image/video
Today: FastAPI receives multipart file. Later: browser can upload directly to S3 with a presigned URL.
2. File bytes go to object storage
Today: artifacts/uploads/file.png. Later: s3://infra-agent-media/inspections/run_123/file.png.
3. SQL stores metadata
The database stores media_id, run_id, MIME type, checksum, size, storage key, and scan status.
4. UI previews safely
Later: the app generates a short-lived presigned URL so the browser can view a private image without making the bucket public.

Retrieval practice

Answer from memory before opening the hint.

Question: In this project, which data should go to S3, and which data should stay in PostgreSQL?

Show answer

S3: large binary objects: uploaded bridge images, videos, annotated images, extracted frames, exported PDFs, maybe model artifacts.

PostgreSQL: structured records: inspection runs, media metadata, checksums, storage keys, severity, plans, schedules, audit events, tool idempotency records.
